# WASSAFRICA — Investor & Partner Data Room Checklist

**Purpose:** préparer une salle de données crédible avant négociation avancée, due diligence ou levée.

## A. Corporate / legal

- [ ] identité juridique de la société ;
- [ ] documents constitutifs ;
- [ ] registre / licences applicables ;
- [ ] cap table à jour ;
- [ ] droits des fondateurs et investisseurs ;
- [ ] contrats importants ;
- [ ] propriété intellectuelle ;
- [ ] marques et domaines ;
- [ ] politique de confidentialité ;
- [ ] conditions d'utilisation ;
- [ ] accords de traitement des données si nécessaires.

## B. Product

- [ ] architecture ;
- [ ] routes critiques ;
- [ ] Smart Link ;
- [ ] messaging ;
- [ ] calls ;
- [ ] commerce ;
- [ ] Partner Network ;
- [ ] assistant commercial ;
- [ ] stratégie multilingue ;
- [ ] dépendances externes.

## C. Proof

Pour chaque fonctionnalité critique :

- [ ] environnement testé ;
- [ ] scénario ;
- [ ] résultat ;
- [ ] date ;
- [ ] preuve ;
- [ ] limitations connues ;
- [ ] statut production.

### Tests prioritaires

1. Compte A → message → Compte B → réponse ;
2. A → appel audio → B accepte → audio bidirectionnel ;
3. A → appel vidéo → B accepte → vidéo bidirectionnelle ;
4. Smart Link → conversation ;
5. Smart Link → assistant basé sur données autorisées ;
6. commerce → paiement uniquement si le parcours est réellement actif ;
7. referral → handoff → outcome lorsqu'un partenaire réel existe.

Ne fournir que des métriques reproductibles :

- utilisateurs inscrits ;
- utilisateurs actifs ;
- entreprises actives ;
- conversations ;
- messages ;
- appels ;
- Smart Links ;
- visites ;
- leads ;
- transactions ;
- GMV ;
- conversion ;
- rétention ;
- CAC ;
- contribution margin ;
- revenus.

Pour chaque métrique : source, période, définition et méthode de calcul.

Si une métrique n'est pas disponible, écrire **N/A / non mesuré** plutôt que produire une estimation présentée comme un résultat.

## H. Fundraising narrative

Le deck et les échanges doivent répondre clairement à :

1. Quel problème ?
2. Pourquoi maintenant ?
3. Pourquoi WASSAFRICA ?
4. Pourquoi cette équipe ?
5. Pourquoi cette distribution ?
6. Pourquoi ce modèle peut devenir grand ?
7. Quelle preuve existe déjà ?
8. Quelle preuve manque ?
9. Quel montant est recherché ?
10. À quelles étapes ce financement mène-t-il ?
11. Quels risques peuvent casser la thèse ?
12. Pourquoi l'équipe est-elle capable de les résoudre ?

## I. Red Team due diligence

Avant de partager la data room, rechercher volontairement :

- incohérences entre produit et pitch ;
- fonctionnalités affichées mais non fonctionnelles ;
- chiffres non sourcés ;
- partenaires seulement « ciblés » mais présentés comme actifs ;
- dépendances critiques non documentées ;
- risques réglementaires ;
- risques de sécurité ;
- coûts d'infrastructure sous-estimés ;
- absence de preuve d'usage ;
- concentration excessive sur une personne ou un fournisseur.

## J. Règle de confiance

> **La data room doit permettre à un investisseur ou partenaire de découvrir aussi ce qui ne fonctionne pas encore.**

La transparence sur les gaps augmente la crédibilité lorsque les plans de correction sont précis et mesurables.

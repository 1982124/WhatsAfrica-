# WASSAFRICA — Partner Research & Outreach Playbook

**Status:** PREPARED — NOT CONTACTED / NOT INTEGRATED

## 1. Mission

Identifier, qualifier and approcher des partenaires capables d'accélérer WASSAFRICA sans lui faire perdre son indépendance, sa simplicité ou sa vérité produit.

WASSAFRICA recherche des partenaires qui apportent au moins une de ces capacités :

- distribution ;
- paiements / services financiers réglementés ;
- télécom / connectivité / APIs réseau ;
- assurance ;
- logistique ;
- diaspora / transferts ;
- infrastructure technologique ;
- acquisition de marchands ;
- accès à des entreprises et PME ;
- capacité d'expansion multi-pays.

## 2. Règle fondamentale

> **Un partenaire potentiel n'est pas un partenaire. Une discussion n'est pas un accord. Un accord n'est pas une intégration. Une intégration n'est pas un résultat.**

Les états doivent rester distincts :

`TARGET → OUTREACH_READY → CONTACTED → DISCOVERY → PILOT_NEGOTIATION → PILOT_APPROVED → INTEGRATING → LIVE_PILOT → CONVERTED → SCALED`

Aucun badge public « partenaire », « intégré », « officiel » ou « live » sans preuve correspondante.

## 4. Fiche de recherche standard

Pour chaque cible, documenter avant tout contact :

- raison sociale exacte ;
- pays / marchés concernés ;
- service pertinent ;
- client cible ;
- problème WASSAFRICA résolu ;
- API / referral / hosted flow disponible ;
- sandbox disponible ;
- exigences contractuelles connues ;
- exigences KYC / conformité ;
- couverture géographique ;
- mécanisme d'attribution possible ;
- modèle économique potentiel ;
- interlocuteur cible ;
- source officielle ;
- date de vérification ;
- niveau de confiance ;
- prochaine action.

## 5. Score de qualification

Attribuer 0 à 5 sur chaque dimension :

| Dimension | Question |
|---|---|
| Strategic fit | Le partenaire résout-il un problème central ? |
| User value | Le parcours devient-il réellement plus simple ? |
| Distribution | Le partenaire apporte-t-il une capacité de distribution ? |
| Integration | Un referral/handoff/API réaliste existe-t-il ? |
| Compliance | Le partage des responsabilités est-il clair ? |
| Attribution | Peut-on mesurer la source et le résultat ? |
| Economics | Une valeur économique contractuelle est-elle plausible ? |
| Geography | Le marché cible est-il pertinent ? |
| Speed | Peut-on lancer un pilote raisonnablement ? |
| Trust | Le partenaire augmente-t-il la crédibilité ? |

**Décision :**

- 40–50 : priorité stratégique ;
- 30–39 : priorité pilote ;
- 20–29 : recherche complémentaire ;
- <20 : ne pas mobiliser l'équipe maintenant.

Ce score est un outil interne, pas une promesse commerciale.

## 6. Questions du premier rendez-vous

1. Quel problème commercial souhaitez-vous résoudre ?
2. Quel parcours voulez-vous distribuer davantage ?
3. Quel mode d'intégration acceptez-vous : referral, handoff, hosted flow, API ?
4. Quelles données sont réellement nécessaires ?
5. Qui conserve KYC, conformité, risque, fraude, settlement et décision réglementée ?
6. Quels événements de résultat pouvez-vous retourner ?
7. Comment attribuer une conversion à WASSAFRICA ?
8. Quel pilote minimal serait acceptable ?
9. Quels sont les critères de réussite ?
10. Quelles conditions permettent le passage à l'échelle ?

## 7. Ce que WASSAFRICA doit demander — et ne pas demander

### Demander

- sandbox ;
- documentation ;
- environnement de test ;
- parcours pilote ;
- attribution ;
- reporting d'outcome ;
- SLA applicables ;
- interlocuteur technique ;
- interlocuteur commercial ;
- conditions contractuelles.

### Ne pas demander au départ

- exclusivité continentale ;
- intégration multi-pays massive ;
- transfert de responsabilité réglementaire ;
- accès excessif aux données ;
- promesse de volume que WASSAFRICA ne peut pas encore prouver.

## 8. Recherche de contacts

Pour chaque partenaire, rechercher en priorité :

- Partnerships / Strategic Partnerships ;
- Business Development ;
- Developer / API Partnerships ;
- Digital Channels ;
- Merchant / SME Partnerships ;
- Innovation / Venture / Ecosystem ;
- Country Manager lorsque pertinent.

Toujours privilégier les canaux officiels et les informations vérifiables.

## 9. Séquence d'approche

**J0 — Recherche**

Comprendre le partenaire et préparer un message spécifique.

**J1 — Premier contact**

Proposition courte + problème concret + demande de discovery call.

**J3–J7 — Relance**

Apporter une information nouvelle : parcours, cas d'usage ou proposition de pilote.

**Discovery**

Qualifier besoin, contraintes et décideurs.

**Pilot negotiation**

Fixer pays, cas d'usage, attribution, sécurité, durée et critères de réussite.

**Pilot**

Mesurer les événements réels.

**Scale**

Étendre seulement si la preuve existe.

## 10. Journal de preuve

Chaque cible doit avoir :

- source officielle ;
- date de vérification ;
- contact ;
- message envoyé ;
- réponse ;
- réunion ;
- décision ;
- contrat si applicable ;
- environnement de test ;
- preuve d'intégration ;
- preuve de résultat.

## 11. Règle Red Team

Avant d'annoncer un partenaire, demander :

> « Quelle preuve indépendante permet à une personne extérieure de vérifier cette affirmation ? »

Si la réponse est « aucune », l'affirmation reste interne et non certifiée.

## 12. Objectif stratégique

WASSAFRICA ne cherche pas à remplacer les grands opérateurs, banques, fintechs ou assureurs.

> **WASSAFRICA veut devenir une couche de découverte, conversation, distribution et orchestration qui leur apporte une demande mieux contextualisée et mesurable, tout en laissant au fournisseur la responsabilité de son service.**
